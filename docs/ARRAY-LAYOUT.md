# Array layout

The new `web/` tool is a dependency-free, orthographic wireframe view. It accepts
portrait/landscape, one to ten modules up slope, one to sixty along the row,
single/opposing faces, azimuth, tilt, lower edge, gaps and module dimensions.
All defaults are synthetic. A 1 GW DC scenario is a quantity calculation rounded
to whole strings; a regular virtual plant places every array at a deterministic address. The overview samples arrays to bound drawing work; any array can be selected by number. It is not a terrain-aware or electrically validated design. Placement edits can be saved locally with settings.

Junction-box count and normalized locations are editable assumptions. Exact
manufacturer mechanical drawings are required before calling a position correct.
Configuration imports are local browser reads, bounded to 1 MB and numeric/
enumerated allowlisted fields. There is no upload, telemetry or external asset.

Private equipment profiles, contract requirements, source hashes and project
identifiers must stay outside this repository and every public deployment.
Removing a name does not anonymize a detailed project model.

Developer-only GPU tools use two numerical formulations plus independent CPU
witnesses. `geometry_loop.py` has a five-hour maximum, an 80 C thermal pause,
bounded VRAM and explicit stop/failure handling. Output belongs on a local drive,
never inside web/. Its coverage concerns synthetic corner coordinates only.
`hourly_check.py` records process health and can write requested local memory
notes. It does not restart failures, claim an AI review or publish results.

The lexical estate inventory checks literal drawing patterns on GPU and CPU.
It does not prove semantic reuse or grant a licence. Keep its full path inventory
private and review provenance before copying any source. Existing vendor files
retain their original terms; new array code was written independently.

Boxes are hidden until their layout is specified. Box fractions follow the module short and long axes when changing orientation. Site overview export contains sampled footprints, not every module.

`cad_wireframe.py` converts local STEP edges to a bounded, sampled SVG for private review using an isolated OCP runtime. It grants no redistribution rights and does not publish source or derived CAD. Curve sampling is a preview, not a manufacturing tolerance.

## Verification and packaging

Run `node --test tests/*.test.mjs`, `python tests/test_public_bundle.py` and
`python tools/check_public_bundle.py`. Hosted browser CI checks presets,
movement, save/reopen, rejected inputs, the final partial array, SVG output,
viewport fitting and absence of remote requests. The deployment gate permits
only the five reviewed web files; adding a data file fails deployment.
This packaging gate does not by itself prove that edited source is anonymous.

The public 1 GW DC scenario's complete regular placement was enumerated on GPU:
1,538,490 modules, 18,461,880 corner coordinate values. Every value was compared
with CPU placement arithmetic; maximum difference was below 1e-12 metres.
The shared module template is covered separately by JavaScript geometry tests.
This is a virtual regular grid, not a surveyed site's constructible layout.

The three-root local code scan covered 58,966 tracked file instances, yielding
27,841 candidate instances and 2,286 distinct normalized candidate contents.
Versions, local modifications, excluded files and repository histories remain
important scope distinctions. Only selected source families have received
semantic/licence review. GPU lexical matching is not an automatic reuse licence.

Movement overlap feedback uses axis-aligned array bounds, including the full
last-array envelope. It is conservative and is not shading or access analysis.
